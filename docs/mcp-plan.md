# План: MCP-коннектор «Семейной бухгалтерии» для Claude

Цель: работать с бюджетом через Claude **под своим аккаунтом** — с телефона (приложение Claude, голосом, фото чека),
с компьютера (Claude Desktop, claude.ai, Claude Code). Claude видит и делает только то, что вы разрешили при
подключении: один проект и выбранные права. Права меняются и доступ отзывается только вами в браузере — через
Claude их не изменить.

**Статус (16.10.2026): первая версия и справочники сделаны** — как подключить, [mcp.md](mcp.md). Отличия от плана ниже:

- **Сервер авторизации — провайдер входа (сейчас Rauthy), а не само приложение** (это «план Б» из раздела 2).
  Своё OAuth в бухгалтерии не делаем: его роль займёт отдельный сервис входа
  ([id-service-prompt.md](id-service-prompt.md)). Приложение — только ресурс: метаданные RFC 9728, `401` с
  `WWW-Authenticate`, проверка JWT access-токена (подпись по JWKS, `iss`, срок, `aud` = `<домен>/mcp`, тип
  токена, без DPoP) в адаптере провайдера (`projects/adapters/oidc.rs`). Крейта `oauth` нет.
- **Проект и права** выбираются заранее на странице «Ассистенты» (`/assistants`, таблица `fb_mcp_grants`), а
  не на экране согласия провайдера; без открытого доступа ассистент видит только подсказку.
- В Claude клиент вводится вручную («свой OAuth-клиент», Client ID `claude`): CIMD и DCR у Rauthy 0.37 с
  Claude не работают.
- Сделаны инструменты чтения, операций и плановых платежей (этапы 1–2).
- **16.10.2026: справочники, курсы, лимиты и планы** (этап 3 без удаления): `add_/update_currency`,
  `add_/update_account` (начальный остаток — ещё и с `transactions:write`), `add_/update_category`, `set_rate`,
  `list_rates`, `set_limit`, `list_limits`, `list_plans`, `add_/update_plan`; права `currencies:write`,
  `accounts:write`, `categories:write`, `rates:write`, `limits:write`, `planning:write` на странице «Ассистенты»
  (по умолчанию выключены, флажок «Все справочники» отмечает первые четыре). Отличия от раздела 4:
  `restore_item` не сделан (возврат из архива — вместе с правом удаления); `set_limit` заменяет правило категории
  с той же датой начала, даже если период другой (в `fb_limits` уникальны категория + `valid_from`); держатель счёта
  через MCP не задаётся.
- Удаление и архив по отдельному праву `delete` (раздел 3, ядро + миграция старых токенов) — следующий шаг.
- Личные API-токены работают на `/mcp` (Claude Code); OAuth-токены провайдера — только на `/mcp`.

Эталон архитектуры — `rust-hex-api` v2.
Сверено с MCP 2026-07-28 и 2025-11-25, документацией коннекторов Claude и `rmcp` 3.5 (октябрь 2026).

## 1. Как это будет работать

```
Claude (телефон / ПК / web)              Claude Code на ПК
   │  облако Anthropic                       │  напрямую
   ▼                                         ▼
https://<домен>/mcp ──── MCP: JSON-RPC по Streamable HTTP, Authorization: Bearer fba_…
   │  auth-слой MCP: токен → грант (права) → пользователь → проект → роль
   ▼
крейт mcp: инструменты ──порты──► сервисы фич (transactions, budget, planning, accounts, categories,
                                  currencies, rates, limits) — прямые вызовы, не HTTP к самому себе
```

**Подключение — один раз.** claude.ai → «Настроить» (Customize) → «Коннекторы» → «+» → «Добавить свой коннектор»,
адрес ровно `https://<домен>/mcp` (без слеша в конце). На Team/Enterprise коннектор добавляет владелец организации,
участники нажимают «Подключить». Дальше коннектор работает в браузере, Claude Desktop, мобильном приложении и в
Claude Code под тем же аккаунтом.

Что происходит при подключении:

1. Claude обращается к `/mcp` без токена → `401` с
   `WWW-Authenticate: Bearer resource_metadata="https://<домен>/.well-known/oauth-protected-resource/mcp", scope="…"`.
2. Читает метаданные ресурса (RFC 9728) и сервера авторизации `https://<домен>/.well-known/oauth-authorization-server`
   (RFC 8414).
3. Представляется **опубликованным идентификатором Claude** (Client ID Metadata Document, CIMD): `client_id` —
   это https-адрес JSON-документа Claude с его именем и адресами возврата. Приложение скачивает документ (только с
   разрешённых хостов) и сверяет `redirect_uri`. Запасной вариант — заранее заведённый клиент `claude`
   («Использовать свой OAuth-клиент» в диалоге Claude).
4. Открывает у вас в браузере `https://<домен>/oauth/authorize?…` (PKCE S256, `resource`) → если вы не вошли —
   обычный вход через Rauthy (с 2FA) → **экран согласия** (раздел 3): проект, права, срок → «Разрешить».
5. Приложение возвращает Claude одноразовый код (`https://claude.ai/api/mcp/auth_callback?code=…&state=…&iss=…`),
   Claude меняет его на `access` (1 час) + `refresh` (ротация) токены.
6. Дальше Claude вызывает инструменты и сам обновляет токен. В профиле — «Подключённые приложения»: права,
   «Изменить права», «Отключить».

## 2. Ключевые решения

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Кто сервер авторизации OAuth | **Само приложение** (небольшой OAuth 2.1 сервер). Пользователь при этом входит как обычно — через Rauthy | Доступ привязан к **проекту и правам**, как личные API-токены, — Rauthy о проектах не знает. Отзыв, журнал, права и список подключений — в нашем профиле; «Выйти везде» и выход из проекта действуют и на Claude |
| Клиенты в первой версии | **Только Claude**: claude.ai, Claude Desktop, мобильное приложение, Claude Code | Приоритет владельца. Другие ассистенты (ChatGPT, Gemini CLI и т. д.) — позже, раздел 11; клиенты устроены как реестр, чтобы добавить их без переделки |
| Регистрация клиента | **CIMD** с белым списком хостов + заранее заведённый клиент `claude`. DCR (`/register`) **не делаем** | В MCP 2026-07-28 CIMD — рекомендуемый способ, DCR объявлен устаревшим. Claude выбирает CIMD, если в метаданных есть `client_id_metadata_document_supported: true` и `"none"` в `token_endpoint_auth_methods_supported`. Без открытой регистрации нет и публичного эндпоинта, через который кто угодно заводит клиентов |
| Что выдаётся Claude | Грант: пользователь + проект + права + клиент. Access-токен `fba_…` (1 час), refresh `fbr_…` (ротация при каждом обновлении, 60 дней с последнего использования); в БД — только SHA-256 | Короткий access-токен ограничивает ущерб при утечке. Повторное использование старого refresh = кража → грант отзывается целиком (OAuth 2.1). Claude требует ротацию refresh для публичных клиентов и `invalid_grant` для мёртвого refresh |
| Где хранятся права | **В гранте, не в токене.** Каждый запрос читает текущие права гранта и текущую роль в проекте | Изменение прав в профиле действует сразу, без переподключения Claude; понижение роли (OWNER сделал вас VIEWER) сразу урезает и Claude |
| Где действует OAuth-токен | **Только на `/mcp`**, только для ресурса `https://<домен>/mcp`. На `/api`, `/oauth/*`, `/profile/*` и страницах — 403 | Наименьшие права; MCP запрещает принимать токены, выпущенные не для этого сервера. Страницы прав и согласия принимают только cookie-сессию браузера с CSRF |
| Изменение прав через MCP | **Невозможно.** В MCP нет ни одного инструмента для прав, грантов, токенов, участников, ролей и настроек проекта; у крейта `mcp` нет порта к ним. Права меняет только человек в браузере | Claude (или текст, подсунутый ему в данных) не может выдать себе больше прав. Расширение — только через экран согласия или профиль, где нажимаете вы |
| Удаление | **Отдельное право**, по умолчанию выключено. Действует только в разделах, где есть право записи. Без него инструменты удаления даже не видны Claude | Решение владельца: по умолчанию удалить ничего нельзя, включить может только сам пользователь |
| Личные API-токены `fbt_` на `/mcp` | Тоже принимаются, с той же моделью прав | Отладка до OAuth и Claude Code с заголовком `Authorization` |
| Транспорт | Streamable HTTP **без серверных сессий, ответы JSON** (без SSE) | В MCP 2026-07-28 сессий и `initialize` больше нет, только `POST`. Старые версии (2025-03-26…2025-11-25, их сейчас использует claude.ai) тоже работают без сессии. Глобальный таймаут 15 с не мешает |
| Библиотека | `rmcp` 3.5 — официальный Rust SDK: сервер Streamable HTTP для Axum 0.8, обе линии протокола, макросы `#[tool]` с аннотациями | Протокол не пишем руками. Авторизацию на стороне сервера `rmcp` не даёт — middleware, метаданные и OAuth наши. Перед подключением — `cargo deny check` |
| Как инструменты зовут логику | Через **порты** крейта `mcp`, адаптеры — в `crates/app/src/wiring/wire_mcp.rs` к публичным `Service` фич | Правило эталона: фичи не знают друг о друге. MCP — ещё один адаптер к тем же use cases, что REST и страницы |
| Проверка прав | `tools/list` отдаёт только разрешённые инструменты; в каждом вызове повторная проверка: `scope_allows(scopes, "<фича>", Read / Write / Delete)` + роль. Отказ — ошибка инструмента с объяснением («права меняются в профиле → Подключённые приложения»), а не HTTP 403 | Что не разрешено — не видно и не вызывается. HTTP 403 оборвал бы весь коннектор, а не один вызов |
| Подтверждения | Аннотации: чтение — `readOnlyHint` (Claude не спрашивает), исправление, архив и удаление — `destructiveHint` (Claude всегда спрашивает). Пользователь может переопределить для каждого инструмента: «Всегда разрешать / Спрашивать / Запретить» | Расход «кофе 120» не должен требовать лишних нажатий, а исправление и удаление — должны |

**Свой сервер авторизации или Rauthy.** Задача узкая: пароли, 2FA и восстановление доступа остаются в Rauthy, а
приложение только выдаёт свой токен (как уже выдаёт личные API-токены) по коду с PKCE и обновляет его — без
открытой регистрации, секретов клиентов и подписи JWT. За это: подключение «только адрес», проект и права на экране
согласия, всё в одном месте, совместимость с Claude чиним сами. Против: свой код, от которого зависит безопасность,
и слежение за спецификацией MCP (авторизация менялась четыре раза за год). Решение обратимо: модулю `mcp` всё равно,
кто выдал токен, — переход на Rauthy = ещё один `Authenticator` с проверкой JWT.

**План Б — Rauthy выдаёт токены, приложение решает права.** Статический публичный клиент Claude в Rauthy
(`allowed_resources = https://<домен>/mcp`, `force_mfa`), в Claude — «Использовать свой OAuth-клиент» с его
Client ID; приложение проверяет JWT по JWKS (`iss`, `exp`, `aud` = адрес `/mcp`), находит пользователя по `sub`, а
проект и права берёт из профиля («Доступ для ассистента» — настраивается заранее). Меньше своего кода, но Client ID
вводится вручную (CIMD Rauthy не объявляет метод `none`, а открытый DCR в Rauthy ограничен одной регистрацией в час
с IP — весь трафик Claude идёт с общих адресов Anthropic), права настраиваются отдельно от подключения, и появляется
зависимость от особых функций Rauthy 0.3x.

## 3. Права

Формат — тот же, что у личных API-токенов (`read`, `<фича>:read`, `<фича>:write`), плюс новое действие **delete**.

| Право | На экране согласия | По умолчанию | Что разрешает |
| --- | --- | --- | --- |
| `read` | Просмотр всего | ☑ | Все инструменты чтения |
| `transactions:write` | Операции: добавлять и исправлять | ☑ | Расход, доход, перевод/обмен, исправление, оплата планового платежа |
| `planning:write` | Плановые платежи | ☐ | Создать, изменить, приостановить план; пропустить / вернуть платёж |
| `currencies:write` | Справочник: валюты | ☐ | Добавить и изменить валюту, вернуть из архива |
| `accounts:write` | Справочник: счета | ☐ | Добавить и изменить счёт, начальный остаток, вернуть из архива |
| `categories:write` | Справочник: категории | ☐ | Добавить, переименовать, перенести категорию, вернуть из архива |
| `rates:write` | Курсы валют | ☐ | Добавить и исправить курс |
| `limits:write` | Лимиты | ☐ | Задать и изменить лимит |
| `delete` | **Удаление и архив** — отдельный блок, выделен красным | ☐ **всегда** | Удалять операции, планы, курсы, лимиты и архивировать валюты, счета, категории — **только в разделах, где отмечена запись** |

Флажок «Справочники» сразу отмечает валюты, счета и категории.

Правила:

- **По умолчанию** отмечены только «Просмотр» и «Операции» — независимо от того, какие права запросил Claude.
  Запрошенные сверх этого показаны неотмеченными с пометкой «запрошено Claude»; «Удаление» не отмечается никогда.
- **Права не выше роли**: VIEWER — только просмотр (запись недоступна для выбора); EDITOR и OWNER — всё из таблицы
  (по ТЗ, раздел 2, справочники и лимиты им доступны). Роль проверяется на каждом запросе.
- **Изменить права** — только в браузере, под своей сессией: профиль → «Подключённые приложения» → «Изменить
  права» (та же форма, что при согласии) или повторное подключение. Проект с «Требовать 2FA» — только после входа
  со вторым фактором.
- **Через MCP не изменить**: токен Claude не принимается на `/oauth/*` и `/profile/*`; инструментов для прав нет;
  обновление токена с `scope` шире выданного — `invalid_scope` (RFC 6749).
- Новые инструменты в списке Claude появляются после изменения прав в новом разговоре (Claude запрашивает список
  инструментов заново); в текущем — проверка на сервере всё равно действует.

**Удаление и в личных API-токенах.** Модель общая: `scope_allows` в ядре получает действие Read / Write / Delete,
REST `DELETE` требует права удаления. Чтобы существующие токены не сломались, миграция добавляет `delete` токенам,
у которых есть право записи; в форме нового токена — те же флажки, «Удаление» по умолчанию выключено.

## 4. Инструменты (первая версия)

Описания инструментов и параметров — по-английски (так модели надёжнее), ответы — короткий текст на языке
пользователя + структурированный JSON. Суммы — строкой или числом, внутри `Decimal`; даты — `YYYY-MM-DD`,
по умолчанию «сегодня». Результат ≤ 150 тыс. символов (лимит Claude) — списки постраничные.

**Чтение** (`read`, `readOnlyHint`)

| Инструмент | Что делает | Сервис |
| --- | --- | --- |
| `get_context` | Проект, базовая валюта, язык, сегодня; счета (код, название, валюта, остаток), дерево категорий (код, названия ru/en/th, вид), валюты; частые категории и счёт по умолчанию; **текущие права** и где их менять. Claude вызывает первым, чтобы «кофе» → `CAFE` | `transactions.quick_defaults`, `categories.nodes`, `currencies.all`, `transactions.balances` |
| `list_transactions` | Операции за период: счёт, вид, автор, категория, текст; страница ≤ 200 | `transactions.list` |
| `get_balances` | Остатки счетов на дату | `transactions.balances` |
| `get_budget` | Бюджет за неделю / месяц / год: лимит, факт, план, прогноз, доступно, уровень (ok / ≥ 80 % / превышение) — это и «сколько осталось по лимитам» | `budget.report` |
| `list_upcoming_payments` | Плановые платежи за период: ожидается / просрочен / оплачен / пропущен | `planning.occurrences` |
| `list_plans` | Плановые и регулярные операции | `planning.list` |
| `list_rates` | Курсы валют за период | `rates.list` |
| `list_limits` | Правила лимитов (категория, период, сумма, с какой даты) | `limits.list` |

**Запись** (право записи раздела)

| Инструмент | Что делает | Сервис | Право | Аннотация |
| --- | --- | --- | --- | --- |
| `add_expense` | Расход: сумма или позиции `[{category, amount, note}]`, счёт (по умолчанию — последний), дата, описание. Возвращает «осталось по категории с учётом предков» | `transactions.create` (EXPENSE) | `transactions:write` | |
| `add_income` | Доход | `transactions.create` (INCOME) | `transactions:write` | |
| `add_transfer` | Перевод между счетами; разные валюты = обмен (`to_amount`); комиссия — категория + сумма | `transactions.create` (TRANSFER) | `transactions:write` | |
| `update_transaction` | Исправить операцию по `id` | `transactions.update` | `transactions:write` | destructive |
| `pay_planned` | Оплатить плановый платёж: операция с `plan_id` + `plan_date`, сумму и счёт можно поправить | `transactions.create` | `transactions:write` | |
| `add_plan`, `update_plan` | Создать / изменить план (в том числе приостановить) | `planning.create`, `update`, `set_active` | `planning:write` | update — destructive |
| `skip_planned`, `unskip_planned` | Пропустить / вернуть плановый платёж | `planning.skip`, `unskip` | `planning:write` | |
| `add_currency`, `update_currency` | Валюта: код, название (ru/en/th), символ, знаки после запятой | `currencies.create`, `update` | `currencies:write` | update — destructive |
| `add_account`, `update_account` | Счёт: код, название (ru/en/th), вид, валюта, держатель; начальный остаток (ещё нужно `transactions:write`) | `accounts.create`, `update`, `set_opening` | `accounts:write` | update — destructive |
| `add_category`, `update_category` | Категория: код, название (ru/en/th), вид, родитель, порядок | `categories.create`, `update` | `categories:write` | update — destructive |
| `restore_item` | Вернуть из архива валюту / счёт / категорию | `*.restore` | `<справочник>:write` | |
| `set_rate` | Курс на дату (добавить или исправить) | `rates.create`, `update` | `rates:write` | |
| `set_limit` | Лимит категории (добавить или изменить) | `limits.create`, `update` | `limits:write` | |

`update_*` справочников **не принимают** поле `archived` (в DTO фич оно есть) — адаптер подставляет текущее
значение, архив возможен только через право удаления.

**Удаление** (право `delete` + запись в том же разделе; `destructiveHint`; без права не показываются)

| Инструмент | Что делает | Сервис |
| --- | --- | --- |
| `delete_transaction` | Удалить операцию; возвращает код отмены на 2 минуты | `transactions.delete_with_undo` |
| `delete_record` | Удалить план / курс / лимит по `id`; код отмены | `planning`, `rates`, `limits`: `delete_with_undo` |
| `archive_item` | Архивировать валюту / счёт / категорию (новые ссылки запрещены, старые сохраняются) | `*.archive` |
| `undo_delete` | Отменить удаление по коду (2 минуты) | `*.undo_delete` |

Каждое удаление через Claude пишется в журнал **вместе с содержимым удалённого** — восстановить можно и после
двух минут.

**Описание на трёх языках.** У операций, планов и справочников есть язык оригинала и переводы ru/en/th. Инструменты
принимают текст + необязательные `translations {ru, en, th}` — Claude сразу заполняет все три языка, и участница с
тайским интерфейсом видит перевод без ручной работы.

**Не будет никогда:** управление проектом, участниками, ролями, API-токенами и правами самого Claude.

## 5. Что меняется в коде

### Новые крейты (тип `blank`, через `arch.py new`)

**`crates/features/oauth`** — OAuth 2.1 сервер поверх сессий приложения.

- Таблицы (миграции фичи):
  - `fb_oauth_codes` — одноразовые коды: хеш, `client_id`, `redirect_uri`, `code_challenge` (S256), `resource`,
    пользователь, проект, права, истекает через 60 с, `used_at`.
  - `fb_oauth_grants` — подключения: пользователь, проект, `client_id` и имя клиента, **права**, хеши текущих
    access/refresh, сроки, `last_used_at`, `revoked_at`, `created_at`, `updated_at` (последнее изменение прав).
- Клиенты:
  - CIMD: `client_id` — https-адрес. Скачиваем только с хостов из `OAUTH_CIMD_HOSTS` (защита от SSRF), без
    перенаправлений, ≤ 16 КБ, таймаут 5 с, кэш в памяти до 24 часов. Документ должен содержать тот же `client_id`, а
    `redirect_uri` запроса — быть в его `redirect_uris` и в `OAUTH_REDIRECT_ALLOWLIST`.
  - Заранее заведённый публичный клиент `claude`: адреса возврата из `OAUTH_REDIRECT_ALLOWLIST` (по умолчанию
    `https://claude.ai/api/mcp/auth_callback`; для Claude Code — `http://localhost:<порт>/callback` и
    `http://127.0.0.1:<порт>/callback`).
- Эндпоинты:
  - `GET /.well-known/oauth-protected-resource/mcp` и `/.well-known/oauth-protected-resource` — RFC 9728:
    `resource: "https://<домен>/mcp"` (ровно как вводит пользователь), `authorization_servers: ["https://<домен>"]`
    (Claude берёт только первый), `scopes_supported`.
  - `GET /.well-known/oauth-authorization-server` — RFC 8414: `issuer`, `authorization_endpoint`, `token_endpoint`,
    `revocation_endpoint`, `response_types_supported: ["code"]`,
    `grant_types_supported: ["authorization_code", "refresh_token"]`, `code_challenge_methods_supported: ["S256"]`,
    `token_endpoint_auth_methods_supported: ["none"]`, `client_id_metadata_document_supported: true`,
    `authorization_response_iss_parameter_supported: true`. `offline_access` не объявляем.
  - `GET/POST /oauth/authorize` — экран согласия (ru/en/th, дизайн-система приложения): имя клиента, адрес
    возврата, выбор проекта, права по разделу 3, срок. Только cookie-сессия: без неё — `/auth/login?next=…`. CSRF как
    у всех форм. Ответ: `code`, `state`, `iss` (RFC 9207). «Отказать» → `error=access_denied`.
  - `POST /oauth/token` (`application/x-www-form-urlencoded`, ответ ≤ 10 с) — `authorization_code` (PKCE S256,
    совпадение `client_id`, `redirect_uri`, `resource`, код одноразовый) и `refresh_token` (ротация, повтор →
    отзыв гранта, мёртвый refresh → `invalid_grant`, `scope` шире выданного → `invalid_scope`). Ошибки — RFC 6749.
    Окно терпимости несколько секунд: если Claude отправит два обновления одновременно, второй получает ту же новую
    пару, а не отзыв гранта «за кражу».
  - `POST /oauth/revoke` — RFC 7009.
  - Профиль → «Подключённые приложения»: клиент, проект, права, когда подключено, последний доступ,
    **«Изменить права»** (форма согласия, сессия + CSRF, событие в журнал), «Отключить».
- Сервис: `authenticate(raw) -> Option<Identity>` для `fba_`-токенов (права — из гранта); порт `AuditLog`
  (адаптер → `projects`).

**`crates/features/mcp`** — MCP-сервер.

- `adapters/mcp.rs` — `StreamableHttpService` из `rmcp` в `Web::public` под путём `/mcp`, со своим auth-слоем:
  токен → `Identity` (с правами) → `Memberships::session` (базовая валюта, язык, роль) → `McpCaller` в расширениях
  запроса; инструменты читают его из `http::request::Parts`. Без токена или с плохим токеном — `401` с
  `WWW-Authenticate`. Настройки `rmcp`: без сессий, ответы JSON, `with_allowed_hosts([<домен>])` (по умолчанию
  `rmcp` пускает только localhost), проверка `Origin` включена. Лимит запросов по гранту/токену. `tools/list`
  фильтруется по правам и роли.
- `ports.rs` — порты к фичам: `Ledger` (операции), `Budget` (отчёт за период), `Plans`, `Directories` (валюты,
  счета, категории), `Rates`, `Limits`, `AuditLog`. Методы удаления — в отдельном порту `Deletions`. **Порта к
  проектам, участникам, токенам и грантам нет.**
- `service.rs` — use cases инструментов: сбор входных DTO из простых параметров (категория по коду или названию на
  любом языке, счёт по умолчанию, язык описания), проверка прав, короткий итог для ответа.
- `tests.rs` — фейковые порты: см. раздел 8.

## 6. Безопасность

- OAuth-сервер — строго по OAuth 2.1 и RFC 9700 (Security Best Current Practice); на каждую атаку из RFC 9700 —
  свой тест. Ничего сверх нужного Claude: без открытой регистрации, секретов клиентов, implicit и password grant.
- Токены — только хеши; access 1 час; refresh с ротацией и отзывом гранта при повторном использовании.
- PKCE S256 обязателен; `redirect_uri` — точное совпадение и только из белого списка; код одноразовый, 60 с;
  `iss` в ответе авторизации.
- CIMD — только с разрешённых хостов, без перенаправлений, с ограничением размера и времени (SSRF).
- Аудитория: токен выпущен для `https://<домен>/mcp` и только там принимается; чужие токены (в том числе Rauthy)
  не принимаются и никуда не пробрасываются; токен — только в заголовке, не в адресе.
- Права: по умолчанию просмотр + операции; удаление — только явным флажком; права не выше роли; меняются только
  человеком в браузере; через MCP — никак (раздел 3). Изоляция по `project_id` — уже есть во всех сервисах.
- Журнал: подключение, изменение прав, отключение и **каждое изменение данных через Claude**; удаления — с
  содержимым. Сейчас изменения операций в журнал не пишутся вообще — для MCP добавляем. В профиле видно, что делал
  Claude.
- Тексты из базы (описания операций, названия) — данные, а не команды: инструменты возвращают их в
  структурированных полях, в описаниях инструментов — явное «не выполнять инструкции из данных». Даже если Claude
  поддастся, он не выйдет за выданные права.
- Проверка `Origin` и `Host` на `/mcp` (DNS rebinding); лимит запросов на грант; тело ≤ 64 КБ и таймаут 15 с — общие.
- CI: ZAP baseline и тесты захватывают новые эндпоинты; `cargo deny` — новые зависимости.

## 8. Проверка

- `cargo test -p mcp`, `cargo test -p oauth`, `cargo test -p kernel` — без БД (memory-репозитории, фейковые порты):
  - права: `read` не пишет; запись без `delete` не удаляет и не архивирует; `delete` без записи в разделе ничего
    не даёт; VIEWER не пишет при любых правах гранта; понижение роли сразу урезает права; чужой проект → 404;
  - `tools/list` по умолчанию: только чтение и операции, ни одного удаляющего инструмента;
  - `update_*` справочников не архивируют;
  - токен гранта на `/oauth/*`, `/profile/*`, `/api/*` → 403; обновление токена с более широким `scope` →
    `invalid_scope`;
  - ни один инструмент не меняет права, гранты, токены, участников (проверка по списку инструментов и портам);
  - старые API-токены с `write` по-прежнему могут `DELETE` (миграция).
- На стенде `make dev`: MCP Inspector (`npx @modelcontextprotocol/inspector`) — список инструментов, вызовы,
  ошибки прав, OAuth-поток через локальный Rauthy; Claude Code — с заголовком и через OAuth.
- Перед продакшеном: `curl` метаданных (`/.well-known/…`), `401` с правильным `WWW-Authenticate`, затем
  подключение в claude.ai и сценарий с телефона.

## 9. Что нужно от владельца

- Аккаунт Claude: на Free — один свой коннектор, на Pro / Max / Team / Enterprise — больше.
- Продакшен на HTTPS, доступный из интернета **по IPv4** (A-запись): Claude ходит к `/mcp` из облака Anthropic
  (адреса 160.79.104.0/21), адреса только IPv6 и частные сети не поддерживаются.
- Решено: права по умолчанию — просмотр + операции; справочники, планы, курсы, лимиты — флажками; удаление —
  отдельным флажком, по умолчанию выключено; через MCP права не меняются.

## 10. Риски и открытые вопросы

- Спецификация MCP меняется быстро: claude.ai пока использует авторизацию 2025-xx и переходит на 2026-07-28;
  `rmcp` 3.5 поддерживает обе линии. Проверять на этапе 4 в реальном claude.ai.
- Адрес документа CIMD Claude (хост для `OAUTH_CIMD_HOSTS`) уточнить по первому реальному запросу на этапе 2; до
  тех пор — клиент `claude`.
- Если Claude Code не поддерживает CIMD — для него остаются клиент `claude` и личный токен в заголовке.
- Статические заголовки в коннекторах claude.ai — бета для части организаций, на них не рассчитываем.
- Одновременные обновления токена — окно терпимости (раздел 5), иначе ложные отзывы подключения.
- После изменения прав список инструментов у Claude обновляется в новом разговоре.
- «Отменить» хранится в памяти процесса (2 минуты) — после перезапуска не сработает; поэтому удалённое через Claude
  дополнительно сохраняется в журнале.
- Лимит запросов, коды отмены и кэш CIMD — в памяти одного экземпляра; при масштабировании — в БД.
- Тайский для экрана согласия — свой перевод (как во всём приложении); страницы Rauthy по-прежнему без тайского.

## 11. Другие ассистенты (после первой версии)

MCP — открытый стандарт, сервер от модели не зависит: права, запрет удаления и неизменяемость прав проверяются на
сервере и действуют для любого клиента. Чтобы подключить другие ассистенты, понадобится только расширить реестр
клиентов в `oauth`:

| Клиент | Что добавить |
| --- | --- |
| ChatGPT (плагин из своего MCP-сервера) | **Сделано 20.10.2026** — без CIMD: свой клиент `chatgpt` в Rauthy и вкладка на странице «Ассистенты» (у каждого ассистента свой доступ), см. [mcp.md](mcp.md#chatgpt) |
| Gemini CLI, Cursor, VS Code | Заранее заведённый клиент «Локальное приложение» (возврат на `http://localhost:<любой порт>/…`) — в Gemini CLI указывается `oauth.clientId`; либо ограниченная DCR (только localhost и адреса из белого списка), т. к. часть клиентов умеет только её |
| Gemini Enterprise / Business | Заранее заведённый клиент, адрес возврата `https://vertexaisearch.cloud.google.com/oauth-redirect` |

Плюс: нейтральные названия в интерфейсе («ассистент» вместо «Claude»), на экране согласия — «подтверждённый клиент»
против «неподтверждённое приложение, вернёт на localhost»; простые схемы параметров инструментов (без `$ref` /
`oneOf` — Gemini их переносит хуже); проверка в Gemini CLI и ChatGPT. Другие клиенты по-своему обращаются с
аннотациями (Gemini CLI спрашивает подтверждение на каждый вызов, если сервер не помечен доверенным), поэтому
безопасность и не опирается на подтверждения клиента.
