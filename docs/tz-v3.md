## Раздел 10. Быстрое добавление расхода

- Точки входа: «+ Расход» в меню, клавиша N (I — доход), круглая «+» на телефоне, «+» в строке категории на «Обзоре».
- Диалог поверх страницы (на телефоне — лист снизу): сумма в фокусе (цифровая клавиатура, «120+45»), 6 частых
  категорий за 30 дней, поиск по дереву на ru/en/th, счёт по умолчанию (последний этого пользователя) с символом
  валюты, «Сегодня / Вчера / Другая…», описание на языке интерфейса.
- «Разбить на позиции» — полная форма с введёнными значениями; «Расход / Доход»; Enter — сохранить,
  Ctrl/Cmd+Enter — сохранить и ещё (счёт и дата остаются), Esc — закрыть.
- До сохранения — «Останется доступно … с учётом предков», янтарное предупреждение ≥ 80 %, красное > 100 %;
  сохранить можно всегда. То же предупреждение — в полной форме с позициями.
- После сохранения — тост «Расход 250 ฿ · Кафе — Отменить», цифры страницы обновляются без перезагрузки (htmx).
- VIEWER кнопок не видит. API: `GET /api/transactions/quick-defaults`, сохранение — `POST /api/transactions`.

Проверено в браузере: добавление, обновление списка и бюджета без перезагрузки, «Отменить».

## Раздел 12. Вход через Rauthy

- `GET /auth/login` → Rauthy: authorization code + PKCE S256, `state`/`nonce`/верификатор — в подписанной cookie на
  10 минут, `ui_locales` — язык интерфейса. «Создать бюджет» → страница регистрации Rauthy (вошедшего — сразу в
  приложение). Ссылки на вход там нет, поэтому на лендинге «Войти» есть и на телефоне, и рядом с «Создать бюджет».
- `/auth/callback`: обмен кода, проверка ID-токена (JWKS, `iss`, `aud`, `nonce`, срок); пользователь — по `sub`;
  новый — онбординг (имя, базовая валюта, язык → личный проект); email и имя обновляются при каждом входе.
- Сессия приложения, токены Rauthy не хранятся; «Выйти» завершает сессию приложения и Rauthy (`end_session_endpoint`).
- `compose.yaml`: контейнер `rauthy` 0.37.1, отдельная БД `rauthy` в нашем PostgreSQL, OTP по email (6 цифр),
  открытая регистрация, клиент `family-budget` и демо-пользователи стенда — из `deploy/rauthy/bootstrap`.

### Этап 0: проверка стенда Rauthy

Проверено на локальном Rauthy 0.37.1 (контейнер, в том числе с PostgreSQL) — полный вход в приложение:

- [x] Discovery, PKCE S256, обмен кода, подпись ID-токена EdDSA по JWKS, `nonce`, `aud`; issuer Rauthy — со слешем
      в конце (`…/auth/v1/`), `OIDC_ISSUER` задаётся так же.
- [x] Rauthy не выдаёт claim `name` — имя собирается из `given_name`/`family_name`/`preferred_username`.
- [x] Клиент и пользователи создаются из `clients.json`/`users.json` при первом старте; секрет клиента — только
      сгенерированный (`"secret": "generate"`), читается `make rauthy-secrets`.
- [x] Rauthy работает с отдельной базой `rauthy` под пользователем без суперправ (54 таблицы).
- [ ] **Выход:** без `id_token_hint` Rauthy спрашивает подтверждение и не возвращает на `post_logout_redirect_uri`
      (остаётся на своей странице). Хранить ID-токен ТЗ запрещает — решение: принять или хранить только
      `id_token_hint` в зашифрованной cookie.
- [ ] **Тайский:** языки страниц Rauthy 0.37 — en, de, fr, ko, nb, nl, ru, uk, zhhans. Русский есть, **тайского нет**:
      нужен свой перевод в Rauthy (PR в проект) или английский для th.
- [ ] Вход через Facebook и GitHub как upstream-провайдеры — нужны ключи приложений Facebook и GitHub.
- [ ] Email-код в `amr` и лимиты попыток/срок кода — нужен SMTP. Приложение считает вторым фактором `amr` с `otp`,
      `mfa`, `hwk`, `swk`, `sms`, `fpt`, `face`, `iris`, `pop`; `claims_supported` Rauthy содержит `amr`.
- [ ] Возврат после регистрации (`/users/register?redirect_uri=`) — не проверялся.

## Раздел 13. Безопасность

| Угроза | Сделано |
| --- | --- |
| Подбор и утёкшие пароли | паролей в приложении нет (`password_hash` удалён миграцией) |
| Подмена входа | PKCE S256, `state` (сравнение за постоянное время), `nonce`, подпись по JWKS, `iss`, `aud`, срок — тесты |
| Кража сессии | `__Host-session` (HttpOnly, Secure, SameSite=Lax), в БД SHA-256, неактивность 7 д, жизнь 30 д, новый id при входе, список устройств, «Выйти везде» |
| CSRF | SameSite=Lax + токен (HMAC от сессии) в каждой форме и в заголовке `X-CSRF-Token` + проверка `Origin`/`Referer` |
| XSS | автоэкранирование Askama, `safe` не используется; CSP без `unsafe-inline`/`unsafe-eval`, все скрипты — файлы со своего домена, ни одного inline-скрипта и `style=""` |
| IDOR | все запросы — по `project_id` из `Scope`; тест «чужой проект → 404» в каждой фиче; роль — на сервере |
| SQL-инъекции | только параметризованные запросы sqlx |
| Утечка БД/логов | паролей нет; id сессий и API-токены — хеши; секреты — из окружения или `*_FILE` |
| Перегрузка | тело ≤ 64 КБ, таймаут 15 с, страница API ≤ 200 записей, лимит запросов на сессию/токен |
| Перехват | HSTS (1 год, includeSubDomains) на HTTPS; CORS — только свой домен |
| Встраивание | `frame-ancestors 'none'`, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` |
| Зависимости | CI: `cargo audit`, `cargo deny`, Trivy, ZAP baseline; Renovate (включая образ Rauthy); образ без root |
| Клиенты без браузера | личные API-токены: права, один проект, срок, показ один раз, хеш, отзыв в профиле |
| 2FA | «Требовать 2FA от участников»: без второго фактора (`amr`) — просьба включить 2FA вместо данных, API — 403 |

Эксплуатация: продакшен не стартует без секретов и HTTPS, Swagger и демо-данные выключены; БД доступна только с
хоста; приложение и Rauthy — разные пользователи БД без суперправ (`deploy/postgres/init-roles.sh`); резервные копии
обеих БД с шифрованием age и хранением 30 дней (`make backup`), проверка восстановления (`make restore-check`);
журнал безопасности (1 год, свои события — в профиле); удаление аккаунта удаляет личные данные и пользователя
в Rauthy (если задан `RAUTHY_ADMIN_API_KEY`), семейные проекты остаются второму владельцу.

Принятый риск: RUSTSEC-2023-0071 (`rsa`, атака Marvin) — `rsa` приходит из `openidconnect` только для проверки
подписи публичным ключом, приватных RSA-ключей нет (`.cargo/audit.toml`, `deny.toml`).

Гостевое демо: общий пользователь `demo:guest` — только просмотр; ему запрещено всё, что меняет общий аккаунт
и проекты (удаление, выход из демо, токены, чужие сессии), а в «Устройствах» он видит только себя.

## Раздел 14. Модель данных

15 таблиц: добавлены `fb_sessions`, `fb_api_tokens`, `fb_audit_log`; у `fb_users` — `rauthy_sub` (уникален),
`avatar_url`, `theme`, без `password_hash`; у `fb_projects` — `require_2fa`. Индекс `fb_transactions_quick_idx` для
быстрого расхода. Миграции проверены на чистой базе и на копии рабочей базы (пользователи до Rauthy получают
`legacy:<id>`, демо-пользователи переносятся с данными).

## Не сделано и ограничения

- **Lighthouse** (≥ 90), Mozilla Observatory, ZAP — не запускались в этой среде; ZAP baseline, Trivy, cargo deny
  настроены в CI. Чек-лист OWASP ASVS уровня 2 — не проходился формально.
- «Отменить» хранит удалённое в памяти процесса (2 минуты) — при перезапуске или нескольких экземплярах не сработает.
  Лимит запросов — тоже в памяти процесса.
- Демо для гостей сбрасывается раз в 24 часа от запуска приложения, а не в фиксированное время.
- Сообщения валидации — по-прежнему только на русском (этап 8 ТЗ); буддийский год для th — следующая версия.
- Пункты стенда Rauthy выше (Facebook, тайский, email-код, выход без подсказки) требуют решения или проверки.
- Скриншот «Обзора» на лендинге — один (русский); для en/th можно снять `SHOT_LANG=en npm run screenshot`.
