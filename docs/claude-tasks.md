# Задачи для Claude через GitHub Issues

Задача заводится коротко, с телефона, в приложении GitHub. Claude сам расписывает её в план и задаёт вопросы.
После одобрения плана он делает PR: сначала тесты, потом код, потом проверка интерфейса со скриншотами.
От вас нужны две вещи: одобрить план и смёржить PR.

```
Issue «Задача для Claude» (метка «claude: план»)
  → Claude: комментарий «План, версия 1» — как понял, вопросы, критерии приёмки, тесты, экраны
  → вы отвечаете комментарием → «План, версия 2» … (сколько нужно)
  → вы ставите метку «claude: в работу»
  → Claude: ветка claude/issue-<N>; коммит с тестами (падают) → код → PR → скриншоты ru/en/th и отчёт в PR
  → правки: комментарий в PR «@claude …»
  → вы мёржите PR (Closes #N закрывает задачу)
```

Workflow: [claude-tasks.yml](../.github/workflows/claude-tasks.yml) (план и реализация),
[claude-pr.yml](../.github/workflows/claude-pr.yml) (`@claude` в PR). Шаблон задачи —
[.github/ISSUE_TEMPLATE/task.yml](../.github/ISSUE_TEMPLATE/task.yml).

## Настроить один раз

1. **Claude GitHub App** установлен на репозиторий: https://github.com/apps/claude → Configure. От его имени Claude
   пушит и открывает PR, поэтому на эти PR запускаются обычные проверки (ci.yml, release-notes.yml).
2. **Токен подписки.** На компьютере с Claude Code: `claude setup-token` — команда выдаст токен для подписки
   Pro/Max. В репозитории: Settings → Secrets and variables → Actions → New repository secret,
   имя `CLAUDE_CODE_OAUTH_TOKEN`.
3. **Метки** «claude: план» и «claude: в работу» создаются сами, когда этот workflow попадает в main (job Labels).
   Если их нет — Actions → Claude tasks → Run workflow.

## Как пользоваться

1. GitHub на телефоне → репозиторий → Issues → «+» → «Задача для Claude». Пара предложений своими словами —
   можно надиктовать.
2. Через несколько минут придёт уведомление о комментарии «План, версия 1». Ответьте на вопросы или поправьте план
   обычным комментарием — Claude опубликует следующую версию. На вопрос можно не отвечать: у каждого есть вариант
   по умолчанию.
3. План устраивает — поставьте метку **«claude: в работу»**. Claude напишет «Взял в работу» со ссылкой на ход работы.
4. Когда появится PR: посмотрите описание, отчёт «Проверка интерфейса» со скриншотами и проверки CI. Нужны правки —
   комментарий в PR, начинающийся с `@claude` (можно и к строке кода в ревью).
5. Всё хорошо — смёржите PR.

Задачу без шаблона тоже можно отдать Claude: поставьте ей метку «claude: план».

## Что важно знать

- **Лимиты подписки.** Работа в Actions расходует тот же лимит, что и ваш Claude Code. Анализ — несколько минут,
  реализация — до двух часов (так ограничен прогон).
- **Сначала тесты.** Первый коммит в ветке — тесты по критериям приёмки, они падают; дальше — код, который их
  проходит. Менять тесты из первого коммита Claude может только отдельным коммитом с объяснением в PR — это видно
  в истории PR.
- **Проверка интерфейса** идёт на чистой базе с демо-данными, в dev-режиме, через «Вход для разработки», без Rauthy:
  страницы входа и регистрации Rauthy так не проверить. Скриншоты лежат в ветке `claude-qa` (в main не попадают),
  старые папки `pr-<N>/` можно удалять.
- **Кто запускает.** Репозиторий публичный: план, реализацию и `@claude` запускают только владелец и участники
  с правом записи, комментарии ботов игнорируются. В Actions Claude запускает cargo, npm, git и gh без
  подтверждений — не вставляйте в задачу непроверенный чужой текст «как есть».
- **Не получилось** — Claude напишет в задаче со ссылкой на лог. Чтобы повторить, снимите и снова поставьте метку
  «claude: в работу»: он продолжит в той же ветке.

## Дальше

Сейчас один агент делает всё по порядку. Когда эта схема приживётся, её можно разделить на отдельные прогоны:
тесты, код (без права менять тесты — проверяет CI), проверка интерфейса. А задачи — вести на доске GitHub Projects
(Входящие → План → В работе → Проверка → Готово).
