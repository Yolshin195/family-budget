# Семейная бухгалтерия — правила для Claude

Приложение (Rust, `crates/`) и сайт (Zola, `site/`) в одном репозитории. Общее описание и команды — README.md,
сайт — site/README.md. Тексты, документация и коммиты — на русском.

## Три языка — всегда

Всё, что видит пользователь, — сразу на русском, английском и тайском, в том же PR. «Переведу потом» не бывает.

- **Приложение:** строки интерфейса, сообщения об ошибках и подсказки — через словари `i18n.rs` (`t("ключ")`);
  демо-данные — с переводами. Тесты `templates_are_translated` в каждой фиче.
- **Сайт:** каждая страница — три файла (`page.md`, `page.en.md`, `page.th.md`) одинакового устройства; скриншоты —
  на каждом языке свои; строки интерфейса — `site/config.toml` [translations]. Проверка: `make site-check`.
- Названия кнопок и разделов в статьях — точно как в интерфейсе на этом языке.

Исключения: данные, которые вводит пользователь (названия, описания операций: пишет на одном языке, приложение
показывает бейдж «нет перевода», через MCP Claude дописывает переводы); документация для разработчиков, комментарии
в коде и коммиты (на русском); страницы и письма Rauthy — в Rauthy 0.37 нет тайского, исправит свой сервис входа
(docs/id-service-prompt.md).

## Задача: идея → код → «Что нового»

Просят сделать то, что заметит пользователь, — по порядку, в одной ветке и одном PR (форматы — site/README.md):

1. **Сначала идея, потом код.** Новая возможность или заметное изменение — статья в `site/content/ideas/` на трёх
   языках со `status = "in_progress"`: какую проблему решаем, что получит пользователь, чего не делаем. Подходящая
   идея уже есть — обновите её и переведите в `in_progress`. Идея — первый коммит ветки и заодно план: задача
   большая или неясная — покажите её и дождитесь согласия, потом пишите код. Исправления ошибок и мелкие правки —
   без идеи.
2. **Код** — с тестами и на трёх языках.
3. **«Что нового» — в том же PR, а не после мёржа.** Три файла в `site/content/releases/next/`; если есть идея, имя
   начинается с её slug (`own-sign-in.md`, `own-sign-in-passkey.md`). Сайт публикуется из `main`, поэтому запись
   появится в блоке «В разработке» как раз в момент мёржа. Пользователь изменений не заметит (рефакторинг, тесты,
   CI) — строка `Changelog: none` в описании PR. Проверяет `.github/workflows/release-notes.yml`.
4. **Гайд** — если новой возможности нужно учиться: `site/content/guides/<slug>/` со скриншотами
   (`scripts/guide-screenshots.mjs`); интерфейс гайда изменился — переснять скриншоты.

Работа на несколько PR — идею отдельным первым PR: она появится на сайте раньше кода. Просят только обсудить или
запланировать — только идея (`discussing` или `planned`), без кода. Идея остаётся `in_progress` до релиза.

Меняется версия в `Cargo.toml` — статья о релизе `site/content/releases/<x-y-z>.md` из записей `next/`, записи
удалить, а идеи, чьи записи вошли в релиз, — `status = "done"` и `release = "releases/<x-y-z>.md"`.

## Лендинг

Новый лендинг — `site/content/_index*.md` (тексты) и `site/templates/index.html`. Лендинг и правовые страницы
в приложении (`crates/features/site`) обслуживают продакшен до переезда сайта на основной домен: их не меняем без
явной просьбы, а правки текста делаем в `site/`.

## Проверки перед PR

- Приложение: `cargo test --workspace` (`make test`), при изменении шаблонов — `make css`.
- Сайт: `make site-check` и `make site` (или `python3 scripts/check_site.py`, `npm run site:assets`, `zola build` в `site/`).
